# Setup

Instructions for Ubuntu 24.04. Run `make check-tools` to see what is installed. The full list of dependencies, with versions and licenses, is in [dependencies.md](dependencies.md).

## Phase 0: model and test programs

```sh
sudo apt-get install gcc-arm-none-eabi libnewlib-arm-none-eabi gcc-riscv64-unknown-elf
curl -LsSf https://astral.sh/uv/install.sh | sh   # if uv is missing
make setup        # also fetches the CoreMark and Embench submodules
make test
```

- `arm-none-eabi-gcc` builds the Thumb test programs (`-mcpu=cortex-m0 -mthumb`), with newlib for the benchmarks.
- `riscv64-unknown-elf-gcc` builds the RISC-V programs. Despite the name it targets RV32 too (`-march=rv32im -mabi=ilp32`).
- `uv` manages the Python environment: Unicorn (ARMv6-M and RV32 reference models), Capstone (disassembly), pyelftools and pytest.

Tests skip when a cross toolchain is missing. Set `THUMBV_REQUIRE_TOOLS=1` to make them fail instead, as CI does.

## Running

### Make targets

| Command | What it does |
|---|---|
| `make setup` | Fetch the submodules and create or update `.venv` from `uv.lock` |
| `make check-tools` | List which toolchains are installed, and which phase needs them |
| `make test` | Run the test suite (about 20 s) |
| `make test-slow` | Also run the slow tests: CoreMark and Embench in lockstep, 500 more random programs (about 5 min) |
| `make clean` | Remove `build/` and Python caches |

### Running tests selectively

`make test` is `uv run pytest`, so any pytest option works through `uv run`:

```sh
uv run pytest -v                      # one line per test
uv run pytest -k thumb                # only tests whose name contains "thumb"
uv run pytest tests/test_smoke.py     # one file
uv run pytest -x                      # stop at the first failure
uv run pytest --slow tests/test_benchmarks.py   # include the slow tests of one file
THUMBV_REQUIRE_TOOLS=1 make test      # fail instead of skip when a toolchain is missing
```

### The test corpus

| File | What it tests |
|---|---|
| `test_rv32.py`, `test_isa.py` | RV32 encoders and the Thumb decode table, against the GNU assemblers |
| `test_lockstep_single.py` | Every encoding, 300 random instances each, one instruction at a time against Unicorn |
| `test_directed.py` | Edge-case programs per instruction class, generated by `gen_directed.py` |
| `test_random.py` | Random instruction sequences, generated by `gen_random.py` |
| `test_lockstep_programs.py` | C programs: a Thumb self-test, mixed RISC-V/Thumb programs, and an ABI check against all-RISC-V builds |
| `test_benchmarks.py` | CoreMark and Embench IoT for Cortex-M0 |

The build recipes for all of these are in `model/thumbv/build.py`, so scripts outside the tests can build the same programs.

The tests build their programs into a temporary directory. To keep the built ELF files for inspection, give pytest a directory:

```sh
mkdir -p build
uv run pytest --basetemp=build/pytest
ls build/pytest/*/                    # one directory per test
```

### The Python environment

`uv run` uses `.venv` automatically, so activation is optional. To work in it interactively, e.g. to load a program built as in the next section:

```sh
source .venv/bin/activate
python -c "from thumbv import elf; print(elf.load('build/smoke_thumb.elf'))"
```

### Building and disassembling a program by hand

The same commands the tests use:

```sh
mkdir -p build
# Thumb (Cortex-M0)
arm-none-eabi-gcc -mcpu=cortex-m0 -mthumb -nostdlib -Wl,-e,_start -Wl,-Ttext=0x1000 \
    -o build/smoke_thumb.elf tests/asm/smoke_thumb.S
arm-none-eabi-objdump -d build/smoke_thumb.elf

# RV32
riscv64-unknown-elf-gcc -march=rv32im -mabi=ilp32 -nostdlib -Wl,-e,_start -Wl,-Ttext=0x1000 \
    -o build/smoke_rv32.elf tests/asm/smoke_rv32.S
riscv64-unknown-elf-objdump -d build/smoke_rv32.elf
```

### Running a program in lockstep

`python -m thumbv.lockstep` runs ELF images in the model and in the reference (Unicorn for Thumb code, a second RV32 executor for RISC-V code) and compares their state after every instruction. The first image's entry point is the start; the run stops at the symbol given with `--stop` (default `done`):

```sh
mkdir -p build
uv run pytest tests/test_lockstep_programs.py --basetemp=build/pytest   # builds the test programs
uv run python -m thumbv.lockstep build/pytest/test_thumb_selftest0/thumb_selftest.elf
uv run python -m thumbv.lockstep build/pytest/test_mixed_program0/main_rv32.elf \
    build/pytest/test_mixed_program0/lib_thumb.elf
```

It prints the number of steps, Thumb instructions and RV32 ops, and r0 at the end. On a divergence it prints the instruction, its expansion, what differs, and the preceding instructions.

### Adding a test program

Assembly:

1. Put the source in `tests/asm/`, with a global `_start` label. For Thumb, mark it `.thumb_func`.
2. Build it with the `build_asm` fixture from `tests/conftest.py`: `build_asm("thumb", "my_test.S")` or `build_asm("rv32", "my_test.S")`. It returns the path of the linked ELF (text at `0x1000` by default).
3. Load it with `thumbv.elf.load(path)` to get its segments, entry point and symbols. See `tests/test_smoke.py` for an example.

C:

1. Put the source in `tests/c/`. There is no C library; libgcc is linked for helper routines.
2. Build a Thumb-only or RV32-only program with `build_c("thumb", "my_test.c")` or `build_c("rv32", ...)`. This adds the startup file (`crt_thumb.S`/`crt_rv32.S`: set SP, call `main`, spin at `done`) and the linker script from `tests/link/`.
3. Build a mixed program with `build_mixed(["lib.c"], ["main.c"])`. The Thumb library is linked first (code at `0x10000`, data at `0x2000_0000`); its global functions become absolute symbols in the RISC-V link (code at `0x20000`, data at `0x2000_4000`). The stack is shared, with its top at `0x2001_0000`.
4. Run it with `thumbv.lockstep.run(images, stop=...)`. See `tests/test_lockstep_programs.py`.

### CI

`.github/workflows/ci.yml` runs `make setup` and `make test` with `THUMBV_REQUIRE_TOOLS=1` on Ubuntu 24.04, on every push and pull request.

## Phase 1 and later

- **Verilator** (`sudo apt-get install verilator`) for RTL simulation. Ubuntu 24.04 ships 5.020.
- **Java and sbt** for SpinalHDL, which generates VexRiscv. Install sbt from [scala-sbt.org](https://www.scala-sbt.org/download).
- **Quartus Prime Lite** for the Cyclone 10 LP, from Intel's website.
- **openFPGALoader** (`sudo apt-get install openfpgaloader`) to program the CYC1000.
